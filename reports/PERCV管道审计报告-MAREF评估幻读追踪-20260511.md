## 一、发现：关键事实错误

### 错误1: 时间线幻读（P0）

**错误位置**: 预测"MAREF在2025-Q4前完成ecosystem建设"，但实际上 MAREF 建设于 2026 年。报告多处出现"2025-Q3"、"2025-Q4"。

**追踪链**:

```
阶段1 信号 → 无日期 ✓
阶段2 KDP → sf-kimi 在 model_b_result 中幻读"2025"和"2019"（但不影响 claim） 
阶段3 投影 → sf-deepseek 在 hypothesis_builder 中幻读 "2025-Q3" ★根因
阶段4 验证 → 接受幻读数据，部分命中判定基于幻读时间线
阶段5 我写的报告 → 未验证日期即输出 ✗
```

**根因**: `HYPOTHESIS_BUILD_PROMPT` 提示词要求 LLM 生成"next 2-4 quarters"的 horizon，但没有提供当前日期上下文。LLM 从训练截止日期推断"now = 2025"。

### 错误2: 预测精确度错位（P1）

报告声称"20%+市场份额"——来自 forecast 的输出。validator 正确识别为"partial"命中，但我的报告未标注这一不确定性。

### 错误3: AutoGen adapter 状态未验证（P2）

报告声称"MAREF已有AutoGen适配器"。这一说法来自信号（我自己创建的），但未通过 PERCV 管道独立验证。应交叉验证 openclaw 代码库中对应的 adapter 文件。

## 三、系统性管道质量问题

### 3.1 事实漂移（Fact Drift）

管道中不存在**事实引用链追踪**机制。每个阶段接收上一阶段的输出并独立推理，没有人验证"这个数字来自哪里"或"这个日期是否一致"。

**修复方案**:
- Prompt 注入: 在 Projector 的 HYPOTHESIS_BUILD_PROMPT 中添加 `Current date: {current_date}` 参数
- 交叉验证: 在 Validator 之前检查预测时间线合理性
- 引用链: 在最终报告添加事实↔KDP↔Signal 的可追溯性

### 3.2 提示词设计缺陷

`projector.py` 的 HYPOTHESIS_BUILD_PROMPT (line 35): `"horizon": "YYYY-QN format (next 2-4 quarters)"` — "next" 是模糊的，应为绝对时间锚点。

### 3.3 验证不完整

Validator 的 `auto_validate_pending()` 通过 LLM 收集实际结果，但 LLM 的输出同样可能包含训练截止日期的错误。如果两个 LLM（projector 和 validator）有相同的训练截止日期，它们会共享相同的盲区。

### 3.4 报告综合缺少验证步骤

PERCV 管道没有"合成"或"报告"阶段。最后一阶段是 Pattern（模式卡片），但不是事实验证。需要增加：
- Stage 6+: **Fact Verify** — 检查所有声明与原始来源的一致性
- Stage 7: **Report Compile** — 从管道输出生成经过验证的报告

## 七、管道改进结论

PERCV 管道在双盲提取（一致性 0.84、100% pass rate）方面表现优秀，但存在两大系统性缺陷：

1. **事实漂移** — 没有引用链追踪，幻读数据可无阻力通过所有阶段
2. **报告综合盲做** — 管道输出→报告的人工步骤缺少事实验证
