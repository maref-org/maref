# Skill: 秋芝风格科技口播文案生成器

> **Skill ID**: `qiuzhi-narrative-style`
> **版本**: v1.0
> **适用场景**: MAREF 短视频脚本、社媒文案、产品科普内容
> **触发词**: `用秋芝风格写`、`秋芝口播`、`灵动解说`、`去爹味文案`
> **核心原则**: 技术翻译成人话，人话翻译得让人愿意听。

---

## 一、风格 DNA（不可违背）

秋芝风格的本质是 **「一个懂技术的朋友在跟你聊天」**，不是「一个专家在给你上课」。

### 1.1 六大基因

| 基因 | 定义 | 正面示例 | 反面示例 |
|------|------|---------|---------|
| **平视** | 「我跟你一样」，不俯视、不仰视 | 「你有没有遇到过这种情况？」 | 「本产品具有以下优势……」 |
| **呼吸** | 短句、停顿、留白、语气词 | 「诶，你发现没？它居然——」 | 「该技术通过优化算法实现了显著的性能提升。」 |
| **起伏** | 情绪有波峰波谷，不是一条直线 | 「我当时就呆了。这什么原理？」 | 「该功能可有效降低延迟，提升吞吐量。」 |
| **去术语** | 每出现 1 个术语，必须配 1 个生活化比喻 | 「KV 缓存就像你背过的单词表」 | 「KV Cache 是一种键值对存储机制。」 |
| **冲突** | 先制造焦虑/好奇，再给解药 | 「你的 Agent 在凌晨三点删了生产库。你查日志？日志里只有一行『任务已完成』。」 | 「MAREF 提供完善的日志审计功能。」 |
| **关系** | 每 3 句话必须有「你」或「我」 | 「我摊牌了，这就是我一直在用的。」 | 「MAREF 已被多家知名企业采用。」 |

### 1.2 语气词库（高频使用）

```
【开场钩子】
诶 / 哎 / 你知道吗 / 你有没有想过 / 我跟你讲 / 说实话 / 坦白说

【转折惊讶】
居然 / 竟然 / 没想到 / 离谱 / 我呆了 / 绝了 / 好家伙

【解释说明】
说白了 / 其实就是 / 相当于 / 你可以理解为 / 打个比方

【强调确认】
真的 / 确实 / 必须 / 千万 / 一定 / 建议 / 记住

【结尾号召】
建议收藏 / 评论区聊聊 / 你细品 / 懂的都懂 / 准备好效率拉满吧
```

### 1.3 去术语化词典

| 技术术语 | 秋芝说法 | 比喻/场景 |
|---------|---------|----------|
| Agent 治理 | 给 Agent 装刹车 | 「你的车再快，没有刹车你敢开吗？」 |
| KV Cache | 单词表 / 备忘录 | 「就像你背过的单词，下次考试直接翻，不用重新背。」 |
| 权限管控 | 查身份证 / 安检 | 「不是谁都能进你的系统，先验身份。」 |
| 日志审计 | 全程录像 / 黑匣子 | 「它干了什么、调了什么 API，全程留痕。」 |
| 熔断机制 | 紧急制动 / 保险丝 | 「一旦发现异常，立刻切断，不是等它把事搞砸。」 |
| 递归演进 | 越用越聪明 | 「你的 Agent 越多，它越聪明。」 |
| 多智能体协作 | 团队协作 / 分工 | 「就像一支球队，有人进攻有人防守。」 |

## 二、七幕剧结构模板（60 秒标准版）

```
总字数控制：150-180 字（中文标准语速 60 秒）
标记语法：[pause] = 停顿 0.5s，[emphasis] = 重音，[emotion:xxx] = 情绪标记
```

### 模板 A：痛点驱动型（最常用）

```markdown
【0-3s 钩子】[emotion:curious]
[语气词] + [反常识问句/陈述]
示例：诶，你有没有想过，你的 Agent 在凌晨三点干了什么，你根本不知道？

【3-8s 痛点放大】[emotion:anxious]
[具体场景] + [恐惧细节] + [无力感]
示例：你的客服 Agent 突然把用户数据发给了竞争对手。你查日志？
日志里只有一行「任务已完成」。你连它怎么想的都不知道。

【8-13s 转折】[emotion:relief]
[所以/说白了] + [一句话定位]
示例：所以我说，Agent 不是缺能力，是缺规矩。MAREF，就是给 Agent 装上的那套规矩。

【13-25s 核心能力】[emotion:confident]
[比喻] + [三层能力，每层一个比喻]
示例：它就像 Agent 的免疫系统。第一，准入——查身份证；
第二，监控——全程录像；第三，熔断——紧急制动。

【25-35s 差异化】[emotion:superior]
[对比] + [记忆点]
示例：别的治理工具像保安，站门口查个身份证就完事了。
MAREF 像管家——它知道每个 Agent 该做什么、不该做什么，而且能自己进化。

【35-45s 社会证明】[emotion:trust]
[具体案例] + [体感数据]
示例：深圳已经有 OPC 企业用它做 Agent 体检了。接入一天，
就测出了 17 个权限漏洞。政府要的是一眼看明白的数据。

【45-55s 使用方式】[emotion:easy]
[降低门槛] + [简单动作]
示例：而且接入简单得离谱。一行代码，你的 Agent 就有了刹车。

【55-60s CTA】[emotion:urgent]
[金句] + [行动号召]
示例：Agent 时代，跑得快不重要，刹得住才重要。MAREF，开源，生产就绪。
链接在评论区。
```

### 模板 B：热点借势型（追 Agent 翻车新闻）

```markdown
【0-3s 钩子】[emotion:shock]
[热点事件] + [反问]
示例：某某公司的 AI 客服又翻车了，把内部报价发给了客户。
你猜他们怎么发现的？客户自己找上门来的。

【3-10s 问题深挖】[emotion:anxious]
[不是个案] + [行业现状]
示例：这不是个案。88% 的企业已经翻过车。Agent 不是不听话，
而是根本没有规矩。它干了什么、怎么干的、有没有越界——你全不知道。

【10-18s 方案亮相】[emotion:relief]
[所以] + [MAREF 定位]
示例：所以我说，Agent 进生产环境之前，必须先过 MAREF 这道安检。

【18-30s 能力演示】[emotion:confident]
[具体场景] + [前后对比]
示例：以前你的 Agent 是裸奔，现在它有了免疫系统。
准入、监控、熔断，三层防护，一层都不能少。

【30-40s 差异化】[emotion:superior]
[对比竞品] + [核心差异]
示例：别的工具像后视镜——出事了才看到。MAREF 像刹车——
在出事之前就让你停下来。

【40-50s 行动门槛】[emotion:easy]
[简单] + [免费/开源]
示例：而且它是开源的。一行代码接入，不用改你现有的架构。

【50-60s CTA】[emotion:urgent]
[金句] + [紧迫感]
示例：Agent 越多，风险越大。MAREF，让你的 Agent 有规有矩。
现在就去试试。
```

### 模板 C：教程/科普型（AI 做表格/工具类）

```markdown
【0-3s 钩子】[emotion:curious]
[你有没有] + [反常识]
示例：你有没有发现，你每次让 AI 做表格，它都在跟你打太极？

【3-8s 痛点】[emotion:frustrated]
[具体困扰] + [场景]
示例：你说「帮我做个销售报表」，它给你一堆文字说明。
你说「直接给我表」，它说「我无法生成文件」。

【8-15s 方案】[emotion:relief]
[其实/说白了] + [工具名]
示例：其实有个工具，专门解决这个问题。它叫 MAREF 的 Agent 工作流。

【15-30s 演示】[emotion:excited]
[步骤拆解] + [效果展示]
示例：第一步，扔给它你的原始数据；第二步，说一句「做成看板」；
第三步，它直接给你一个可交互的可视化页面。全程用嘴说就行。

【30-40s 对比】[emotion:superior]
[以前 vs 现在]
示例：以前你一格一格填、一个公式一个公式调。现在你说句话，
它 10 秒出图。

【40-50s 适用人群】[emotion:inclusive]
[不管你是...]
示例：不管你是运营、行政、财务，还是老师、学生，
只要你要跟数据打交道，这个都能帮你效率拉满。

【50-60s CTA】[emotion:urgent]
[资料包] + [关注]
示例：我把今天的技巧和拓展用法整理成了文档，放在评论区。
建议收藏，下次用的时候翻出来看。准备好效率拉满吧！
```

## 四、质量检查清单（Agent 自检用）

脚本生成后，Agent 必须逐条检查，不通过则重写。

### 4.1 脚本层检查

- [ ] **钩子检查**：前 3 秒是否是问句或反常识陈述？
- [ ] **视角检查**：全文「你」+「我」出现次数 ≥ 总句数 × 30%
- [ ] **节奏检查**：每 10 秒至少 1 个 [pause] 或语气词
- [ ] **情绪检查**：60 秒内情绪标记变化 ≥ 3 次（不能一条直线）
- [ ] **术语检查**：每出现 1 个技术术语，必须有 1 个比喻/场景解释
- [ ] **去爹味检查**：没有「本产品」「本系统」「众所周知」「毋庸置疑」
- [ ] **CTA 检查**：结尾是否是感叹句或反问句？是否让人想截图？

### 4.2 视觉层检查（供 Remotion 使用）

- [ ] **钩子画面**：前 3 秒是否有大字标题或强对比画面？
- [ ] **数据动画**：每个数字是否有放大/弹跳动画？
- [ ] **转场节奏**：转场时长 ≤ 0.3s，不拖沓
- [ ] **字幕同步**：字幕与口型/文案误差 < 0.2s
- [ ] **留白检查**：信息密度是否过高？每 15 秒是否有 1 个「呼吸帧」？

### 4.3 数字人层检查（供 Athena 使用）

- [ ] **表情检查**：Athena 是否保持微笑？（严肃场景除外）
- [ ] **眼神检查**：视线是否正对镜头？
- [ ] **口型检查**：口型与音频同步误差 < 0.1s
- [ ] **位置检查**：小头像不遮挡核心信息（数据、代码、CTA 按钮）

## 八、短版模板（15-30 秒）

> 七幕剧是为 60 秒设计的。15-30 秒短视频需要**浓缩为五幕**，每幕对应一句独立的话。
> 核心原则：**每句文案 = 一个画面 = 一段旁白**，三者必须对齐。

### 8.1 五幕结构（15 秒标准版）

```
总字数控制：20-30 字（中文标准语速 15 秒）
标记语法：[M] = 男声, [F] = 女声（用于双 TTS 交替）
```

```markdown
【0-2s 钩子】[M] [emotion:curious]
一句话反常识问句，直接命中用户
示例：你的 Agent 有规矩吗？

【2-4s 痛点】[F] [emotion:anxious]
一句话后果/恐惧，极短极有力
示例：没规矩随时翻车。

【4-6.5s 方案】[M] [emotion:relief]
一句话方案亮相，必须带生活化比喻
示例：MAREF 给 Agent 装刹车。

【6.5-10.5s 价值】[F] [emotion:confident]
三个价值点，用分隔符串成一句
示例：开源 · 一行接入 · 越用越聪明。

【10.5-15s CTA】[M] [emotion:urgent]
品牌名 + 金句，必须让人想截图
示例：maref.cc 有规有矩。
```

### 8.2 声线分工规则

| 角色 | 负责段落 | 推荐音色 | 功能 |
|------|---------|---------|------|
| **男声** | 钩子 + 方案 + CTA | 快乐小东 2.0 | 自信、坚定、权威 |
| **女声** | 痛点 + 价值 | Tina 老师 2.0 | 亲切、可信、共情 |

- 男声以问句开场建立权威，女声以痛点建立共情
- 方案段回到男声形成「解药感」
- 女声的价值段建立信任后，男声的 CTA 形成收束

### 8.3 15 秒文案字数速查

| 段落 | 理想字数 | 朗读时长 | 情绪 |
|------|---------|---------|------|
| 钩子 | 5-8 字 | ~1.5s | 好奇/反常识 |
| 痛点 | 4-7 字 | ~1.5-2s | 焦虑/紧迫 |
| 方案 | 7-12 字 | ~2-2.5s | 释然/自信 |
| 价值 | 8-15 字 | ~3.5-4.5s | 骄傲/共鸣 |
| CTA | 5-10 字 | ~3.5-4.5s | 紧迫/行动 |

15 秒总字数控制在 **25-35 字**，单句不超过 15 字。每多 1 字增加约 0.25s。

## 九、视频同步规则（旁白 ↔ 画面 ↔ 字幕）

> 这是解决「字幕和旁白对不上」的根本规则，来自实战验证。

### 9.1 黄金三对齐

```
每段旁白 → 独占一个 cut → 画面文字 = 旁白原文
```

**不得违反：**
1. 每个旁白段落必须有独立 cut，cut 数量 = 旁白段落数
2. cut 的 `in_seconds` / `out_seconds` 必须与该段旁白的起止时间对齐
3. cut 的 `text` 必须等于该段旁白的文字内容（一模一样）

**常见错误：**
- ❌ 多个旁白段落共用同一个 cut（字幕停留时间不对）
- ❌ cut 文字是旁白的概括而非原文（口型对不上、用户困惑）
- ❌ cut 进出时间与旁白段落边界不一致（画面提前切换或延迟消失）

### 9.2 正确做法

```yaml
# 正确的 cut 结构示例
cuts:
  - id: hook       # 旁白: "你的 Agent 有规矩吗？" (0-1.6s)
    in: 0          #   → cut 从 0 开始
    out: 1.7       #   → cut 到 1.7s（略晚于旁白结束，留呼吸）
    text: "你的 Agent 有规矩吗？"

  - id: pain       # 旁白: "没规矩随时翻车。" (1.6-3.9s)
    in: 1.7        #   → cut 从 1.7s 开始
    out: 4.0       #   → cut 到 4.0s
    text: "没规矩随时翻车。"
```

### 9.3 背景图选图规则

| 段落 | 配图方向 | 搜索关键词（Pexels） | 覆盖层 |
|------|---------|---------------------|-------|
| 钩子 | 思考/疑问/科技感 | question, thinking, robot | 0.55-0.6 |
| 痛点 | 混乱/破损/警示 | broken, error, mistake | 0.6-0.7 |
| 方案 | 保护/控制/安全 | shield, protection, control | 0.5-0.55 |
| 价值 | 智能/网络/代码 | code, network, abstract, digital | 0.5-0.55 |
| CTA | 治理/规则/品牌 | governance, rules, futuristic | 0.55-0.65 |

**Pexels 使用贴士：**
- 不用 API Key，直接请求 `api.pexels.com/v1/search`
- 查询词必须用**单个单词**（多词组合返回空结果）
- 指定 `orientation=landscape` 获得 1920×1080 兼容图片
- 图片叠加深色半透明层（backgroundOverlay）确保文字可读

### 9.4 常用背景图覆盖层值速查

| 场景 | overlay 值 | 效果 |
|------|-----------|------|
| 深色背景 + 白色大字 | 0.55-0.6 | 文字清晰，图片隐约可见 |
| 浅色/杂乱背景 | 0.65-0.75 | 压制背景干扰 |
| 纯气氛图（无文字区域） | 0.4-0.5 | 保留更多图片细节 |

## 十、TTS 配音工作流

### 10.1 Volcengine Doubao Speech API

```
API: openspeech.bytedance.com
Endpoint: POST /api/v3/tts/submit → 异步 → POST /api/v3/tts/query
Resource ID: seed-tts-2.0
认证: X-Api-Key + X-Api-Resource-Id + X-Api-Request-Id
```

**可用音色（2.0 系列，已验证）：**
- 快乐小东 2.0: `zh_male_kuailexiaodong_uranus_bigtts`（男声）
- Tina 老师 2.0: `zh_female_yingyujiaoxue_uranus_bigtts`（女声）

**提交 body 格式：**
```json
{
  "user": {"uid": "openmontage"},
  "unique_id": "<uuid>",
  "req_params": {
    "text": "要合成的文本",
    "speaker": "zh_male_kuailexiaodong_uranus_bigtts",
    "audio_params": {"format": "mp3", "sample_rate": 24000, "speech_rate": 0},
    "additions": "{\"disable_markdown_filter\": false}"
  }
}
```

### 10.2 多段 TTS 拼接

**禁止**直接 `cat` 拼接 MP3 文件（会产生爆音/损坏）。
**必须**使用 ffmpeg concat demuxer：

```bash
# 1. 创建文件列表
printf "file '%s'\n" /tmp/seg1.mp3 /tmp/seg2.mp3 /tmp/seg3.mp3 > /tmp/concat.txt

# 2. ffmpeg 拼接
ffmpeg -f concat -safe 0 -i /tmp/concat.txt -c copy /tmp/output.mp3
```

### 10.3 时长预估

中文语速 ≈ **3-4 字/秒**（TTS 自然语速，speech_rate=0）：
- 5 字 = ~1.5s
- 8 字 = ~2.2s
- 15 字 = ~4.2s
