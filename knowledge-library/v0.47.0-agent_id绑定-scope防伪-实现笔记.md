# v0.47.0 S12 agent_id 绑定 + scope 防伪 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P1 第四项 —— 授权范围防伪

## 概述

v0.46.1 深度审计定位两处授权范围漏洞：
1. **无主体绑定** —— `TrustBoundaryManager._evaluate` 使用 scope 但不校验
   `scope.subject_did == agent_id`，任何 agent 可用别人的授权范围证书；
2. **无签发者验签** —— `AuthorizationScope` 无签名，伪造 issuer 的 scope 无法识别。

本迭代为授权范围增加主体绑定 + 签发者 Ed25519 验签（防伪）。

## 交付物

### `src/maref/identity/credential.py`

- `AuthorizationScope` 增加 `signature: str = ""` 字段，`to_dict()` 透出。
- 新增 `canonical_payload()`：覆盖全字段（subject_did/max_risk_level/排序后
  allowed_actions/valid_until/jurisdiction/issuer）的规范字节，供签名/验签。
- 新增 `sign(signing_key)`：用签发者 `ReportSigningKey`（Ed25519）签名。
- 新增 `verify_signature(public_key_pem)`：用签发者公钥验签（无签名/无公钥 → False，fail-closed）。

### `src/maref/governance/trust_boundary.py`

- `TrustBoundaryManager.__init__` 增加 `issuer_public_keys: dict[str, str] | None`
  （issuer DID → Ed25519 公钥 PEM）。
- `_evaluate` 在目标域校验后、风险分级放行前统一加两道校验：
  1. **subject_did 绑定**：`_subjects_match(scope.subject_did, agent_id)`，不匹配 → 拒绝。
  2. **签发者验签**：`scope.issuer in issuer_public_keys` 时
     `scope.verify_signature(issuer_public_keys[issuer])`，失败 → 拒绝（伪造 scope）。
- 新增 `_subjects_match` 辅助：兼容 DID（`did:maref:agent-01`）与短名（`agent-01`）
  两种标识，DID 尾部匹配（`:agent-01` / `/agent-01`）。

## 设计决策

| 决策 | 理由 |
|------|------|
| subject_did 校验放目标域检查后、风险放行前 | 任何 scope 使用（LOW/MEDIUM/HIGH）都需主体匹配；先验证身份再谈授权 |
| `_subjects_match` 兼容 DID/短名 | 既有测试用完整 DID + 短名 agent_id；避免破坏兼容 |
| 签发者验签仅在 issuer 在公钥表时强制 | 未配置公钥表保持向后兼容；配置即 fail-closed（伪造 issuer 拒绝） |
| 签名 payload 覆盖全字段 | 任一字段篡改（allowed_actions/max_risk_level 等）都会使签名失效 |
| `verify_signature` 无签名/无公钥返回 False | fail-closed；未签名 scope 在配置验签时必然拒绝 |
