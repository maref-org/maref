# v0.47.0 S4 信任报告签名 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P0 第四项 —— 信任报告签名（PeerTrustReport 来源认证）

## 概述

v0.46.1 深度审计定位 `federation/trust.py` 一处 fail-open：
**`submit_peer_report` 对报告来源零认证** —— 任何进程可伪造 `source_server` 提交任意信任评分，
配合 S1 修复前的零认证 HTTP 传输可远程污染联邦信任聚合结果（信任毒化）。

本迭代以 TDD 方式为信任报告增加 Ed25519 来源签名，配置后 fail-closed 丢弃无效签名报告并留审计痕迹。

## 交付物

### `src/maref/federation/trust_hardening.py`（签名辅助，与 Sybil 防护同域）

- `peer_report_payload(report) -> bytes` —— 报告规范载荷：
  `agent_id\nsource_server\ntrust_score!r\ntier\ntimestamp!r\nconfidence!r`。
  覆盖对接收方有意义的全部字段；字段顺序/格式一旦发布不可变更（否则旧报告验签失效）。
- `sign_peer_report(report, signing_key, key_id) -> report` —— 就地签名并回填
  `signature` / `signer_key_id`，复用 `ReportSigningKey.sign_report`（Ed25519）。
- `verify_report_signature(report, trusted_public_keys) -> bool` —— 按 `signer_key_id`
  （缺省回退 `source_server`）查公钥表，验签规范载荷；永不抛异常，fail-closed。

### `src/maref/federation/trust.py`（引擎集成）

- `PeerTrustReport` 增加 `signature: str = ""` / `signer_key_id: str = ""` 字段，`to_dict()` 透出。
- `FederatedTrustEngine.__init__` 新增 `trusted_peer_public_keys: dict[str, str] | None = None`
  （key_id → Ed25519 公钥 PEM）。
- `submit_peer_report`：配置公钥表时先验签，无效则 `_record_rejected_report` 丢弃并返回；
  未配置时保持历史行为（向后兼容，既有 e2e 提交无签名报告不受影响）。
- 审计可观测：
  - `trusted_peer_count` / `rejected_report_count` 属性
  - `rejected_reports(limit)` 返回被拒报告记录（`reason: "invalid_signature"`），cap 500
  - `federated_summary()` 增加 `trusted_peer_count` / `rejected_report_count`

### `src/maref/federation/federation_http.py`（传输透传）

- `_report_from_dict` 读取 `signature` / `signer_key_id`，使经 HTTP 提交的报告保留签名，
  与 S1 请求签名叠加：传输层身份（S1）+ 报告内容来源（S4）双重认证。

### fail-open 复现与封堵

- **复现**：构造 `PeerTrustReport(source_server="org-evil", trust_score=0.0)` 直接
  `submit_peer_report`，引擎无任何身份校验即入 `_peer_reports`，参与聚合压低目标信任分。
- **封堵**：`trusted_peer_public_keys` 配置后无签名 / 伪造签名 / 篡改字段 / 未知 signer 一律丢弃，
  且 `rejected_reports()` 留审计；未配置时行为不变（生产接线配置即闭环）。

## 设计决策

| 决策 | 理由 |
|------|------|
| 显式配置启用、默认向后兼容 | 既有 e2e 与 trust 测试全部无签名构造；与 S1/S2 同策略，符合规划 R1 两步走 |
| 签名辅助放 trust_hardening 而非新模块 | 规划落点即 `trust.py` + `trust_hardening.py`；模块 docstring 已声明「不 import trust 避免循环」——辅助函数用鸭子类型不依赖 PeerTrustReport 类 |
| payload 用 `!r` 表示浮点 | 保证同值不同构造的浮点字符串一致（`repr` 稳定），跨 JSON 序列化后仍可复验 |
| signer_key_id 缺省回退 source_server | 使「以 source_server 为 key_id」的简单部署无需额外字段 |
| 拒绝记录保留最近 500 条 | 防审计列表无界增长；`federated_summary` 提供计数 |

## 与 S1 的关系

S1 认证「谁发的 HTTP 请求」，S4 认证「报告内容来自哪个 peer」。
生产接线建议：S1 `request_verifier` 与 S4 `trusted_peer_public_keys` 使用同一份 peer 公钥表
（同 key_id），传输身份与内容来源双重验证。
