## 概述

v0.46.1 深度审计定位：**`MultiAgentCoordinator` 零治理接线（0 测试）**——多 Agent 编排
派发前无 TrustBoundary 门禁、任务无审计/计量、执行异常无级联断路器，是联邦治理的盲区。

本迭代把 `MultiAgentCoordinator` 接入联邦治理，补齐单元 + 集成测试。

## 交付物

### `src/maref/execution/multi_agent/coordinator.py`

`MultiAgentCoordinator.__init__` 新增 4 个可注入治理组件（全部默认 None，向后兼容）：

| 组件 | 治理点 |
|------|--------|
| `boundary: TrustBoundaryManager \| None` | 派发前门禁：`_boundary_allows` 对每个 agent 执行 `check_no_raise(task or role:role, agent_id)`，越界 → 跳过该 agent（FAILED，fail-closed） |
| `audit_bus: AuditBus \| None` | 任务审计：`_record_audit` 记录 `multi_agent_task` 事件（actor=agent_id, metadata 含 role/status） |
| `metering: TaskMeteringEngine \| None` | 任务计量：`_record_metering` 记录 `TaskMetric`（caller_did=agent_id, success 实测定） |
| `circuit_breaker: CircuitBreaker \| None` | 级联断路器：`_execution_failed` 触发 `record_failure`；`_breaker_open` 时停止后续派发（FAILED） |

重构：
- 原 `_run_sequential`/`_run_parallel` 的执行体抽为 `_dispatch`（统一门禁 + 审计 + 计量 + 熔断），
  顺序/并行共用同一治理路径。
- `_run_sequential` 在每个 agent 后检查断路器，打开即 break。
- 并行路径在锁内调用 `_dispatch`（线程安全）。

## 设计决策

| 决策 | 理由 |
|------|------|
| 组件全部可注入、默认 None | 与 S1–S13 一致"显式配置启用、默认兼容"；既有调用零改动 |
| `_dispatch` 统一治理路径 | 顺序/并行共享同一门禁+审计+计量+熔断逻辑，避免双实现漂移 |
| 派发前 boundary 门禁 | 与 S9（单 Agent pipeline 门禁）对齐：跨组织派发动作与本地执行同门禁 |
| 计量 `success` 实测定 | 复用 S5 原则（执行器实测，禁止调用方注入） |
| 断路器在 `_dispatch` 前检查 + 顺序循环 break | 熔断后级联停止，避免无效派发 |
