# v0.47.0 S10 RuntimeBehaviorProbe 运行时装配 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P1 第二项 —— 行为审计闭环运行时装配

## 概述

v0.46.1 深度审计定位：**RuntimeBehaviorProbe（v0.44 S2 已实现）无生产启动点**——探针核心逻辑
完整（审计事件→AgentEvent→基线→异常检测→信任扣减→熔断降级），但没有任何 sidecar/编排层装配并
`start()`，行为闭环在运行时是断开的。同时探针默认订阅 `"*"` 全量事件流，误报与开销大。

本迭代提供标准装配点 + 收窄事件订阅。

## 交付物

### `src/maref/agent/behavior_analyzer.py`

- `RuntimeBehaviorProbe` 支持 `subscribed_topics: tuple[str, ...] | None` 参数：
  - 提供时订阅这些精确 topic（治理事件）；缺省回退 `(event_topic,)`（原 `"*"` 行为，向后兼容）。
  - `start()`/`stop()` 遍历订阅/退订所有 topics；`subscribed_topics` 属性暴露当前订阅。
- `_BEHAVIOR_EVENT_PREFIXES` 加入 `"state_transition"`、`"audit"`（探针能识别治理事件中的行为特征）。
- 新增 `assemble_runtime_behavior_probe(audit_bus, trust_engine, circuit_breaker, window_size,
  subscribed_topics)`：标准装配点。组件可注入或自建（AuditBus/TrustEngineV2/CircuitBreaker），
  默认 `subscribed_topics=("state_transition", "audit")` 收窄订阅，返回已 `start()` 的探针。
- 顺带修复 `generate_report` 的 mypy strict 基线错误（`report: dict[str, Any]` 显式类型）。

### `src/sidecar/server.py`

- `_setup_routes` 装配 `app.state.behavior_probe = assemble_runtime_behavior_probe()`——
  sidecar 启动即装配并 start，行为闭环进入运行时。独立 AuditBus 实例，不影响 HTTP 行为。

## 设计决策

| 决策 | 理由 |
|------|------|
| `subscribed_topics` 参数 + `(event_topic,)` 缺省 | 向后兼容既有测试（默认 `"*"` 行为不变）；收窄由装配层显式给出 |
| 装配函数默认 `("state_transition", "audit")` | 规划明确「收窄到治理事件」；比全量 `"*"` 降误报/开销 |
| `_BEHAVIOR_EVENT_PREFIXES` 加 state_transition/audit | 探针能识别收窄后收到的治理事件；`governance_decision`/`compliance_decision` 仍被忽略（不以这些前缀开头/结尾），既有测试 `test_non_behavioral_events_ignored` 不受影响 |
| 装配放 `_setup_routes` 而非 create_app 外层 | 与 MCP gateway、metric store 等 sidecar 组件同生命周期；`app.state` 暴露供运维查询 |
| 组件可注入可自建 | 测试/编排层可注入共享 AuditBus 打通审计流；默认自建独立实例零副作用 |
