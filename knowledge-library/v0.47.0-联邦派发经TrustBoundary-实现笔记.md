# v0.47.0 F3 联邦派发经 TrustBoundary 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P1 联邦治理闭环第三项 —— 联邦派发与本地执行同门禁

## 概述

v0.46.1 深度审计定位：**联邦派发（`FederatedPlanExecutor._dispatch_step`）无 TrustBoundary
门禁**——跨组织派发动作直接进 gateway，而本地执行已通过 S9 接入 GovernancePipeline 的
TrustBoundary 强制门禁。跨组织动作与本地动作门禁不一致，攻击者可绕过分界直接派发高风险任务。

本迭代为联邦派发接入 TrustBoundary 边界校验（与本地执行同门禁）。

## 交付物

### `src/maref/orchestration/federated_plan_executor.py`

- `FederatedPlanExecutor.__init__` 新增 `boundary: Any | None = None` 参数。
- `_dispatch_step` 在创建 record 后、capability 校验前：
  `self._boundary.check_no_raise(action=action, agent_id=consumer_org or "federated",
  metadata={"capability": capability, "provider_org": provider_org})`；
  越界 → `record.error = "TrustBoundary denied dispatch: <reason>"`，返回 record
  （fail-closed，不计计量）。
- 未注入 `boundary` → 行为不变（向后兼容，既有 executor 测试零改动）。

## 设计决策

| 决策 | 理由 |
|------|------|
| `boundary` 参数可注入、默认 None | 与 S1–F2 一致"显式配置启用、默认兼容" |
| 校验放 capability 校验前 | 边界是身份/授权层，应先于参数校验；越界即短路 |
| `agent_id=consumer_org` | 联邦派发中 consumer（请求方）是动作主体，与 S5 计量 caller_did 一致 |
| metadata 带 capability/provider | 供 `classify_action` 风险分级（impact_scope 等） |
| 越界不计量 | 未执行的派发不产生计费（与 S5 success 实测一致） |
| 与 S9 同 TrustBoundaryManager | 本地（GovernancePipeline）与联邦（executor）共用同一边界语义 |
