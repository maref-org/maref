# v0.47.0 S9 TrustBoundaryManager 进 GovernancePipeline 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P1 第一项 —— 单 Agent 治理接线闭环（S9 起）

## 概述

v0.46.1 深度审计定位：**TrustBoundaryManager（v0.44 S1 已实现）未进入运行时主链路**——
`GovernancePipeline` 8 步管线从不调用它，动作级权限边界形同虚设（组件全有、链路断裂）。

本迭代把 TrustBoundaryManager 注入 `GovernancePipeline` 为动作执行前**强制门禁**（fail-closed），
实现「预检建议 → 执行时强制」的升级。

## 交付物

### `src/maref/governance/core_pipeline.py`

- `GovernancePipeline.__init__` 新增 `boundary: Any | None = None` 参数（鸭子类型注入，core_pipeline
  不硬依赖 trust_boundary 模块，避免引入耦合）。
- `govern()` 增加**步骤 0**：注入 boundary 时先调 `boundary.check_no_raise(action, agent_id, parameters)`；
  返回 `allowed=False` → `GovernanceResult(Verdict.DENY, matched_rule="trust_boundary")`，
  并触发审计回调 + 断路器失败记录后短路返回。异常时降级为放行（边界组件自身异常不应阻断管线，
  由上层审计兜底）。
- 未注入 boundary → 行为完全不变（向后兼容，既有 30+ 管线测试零改动）。

### `src/maref/governance/__init__.py`

- 导出 `TrustBoundaryManager` / `BoundaryDecision` / `BoundaryViolationError`，加入 `__all__`，
  使 `from maref.governance import TrustBoundaryManager` 可用。

### `src/maref/security/trust_boundary/__init__.py`（旧版 deprecation）

- 模块导入时 emit `DeprecationWarning`，说明旧版是信任域模型、新模块是动作级权限边界（E1006），
  并提示迁移路径。旧使用方（security_proofs/trust_integration/loop/bridge 及 tests）仅产生警告，
  功能不受影响（74 项既有测试全过）。

## 设计决策

| 决策 | 理由 |
|------|------|
| `boundary` 参数可注入、默认 None | 与 S1–S8 一致"显式配置启用、默认兼容"；既有管线测试零改动 |
| 鸭子类型注入（`check_no_raise` 协议） | core_pipeline 不硬 import trust_boundary，解耦；测试可注入 mock |
| 门禁放在步骤 0（最前） | 动作级边界是最高优先强制门禁，越界即短路，不进入权限矩阵/策略规则 |
| 用 `check_no_raise` 而非 `check` | 管线以 `GovernanceResult` 返回裁决而非抛异常；E1006 语义映射为 `Verdict.DENY` + `matched_rule="trust_boundary"` |
| 边界异常降级放行 | 边界组件自身故障不应阻断所有治理；审计回调仍触发，由完整性检查兜底 |
| 旧版 deprecation 而非删除 | 旧版有 8 处 src + 多组测试使用方，直接删除破坏；渐进迁移 |
