# v0.47.0 S5 计量/计费注入封堵 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P0 第五项 —— 计量来源绑定 + success 实测定

## 概述

v0.46.1 深度审计定位计量/计费链路两处注入风险：
1. **计量无来源绑定** —— `TaskMetric` 不记录谁提交了计量，无法追溯/审计跨组织计费数据来源；
2. **success 可被调用方注入** —— `federated_plan_executor._dispatch_step` 直接读
   `params.get("success", True)` 作为计量 success，调用方可注入 `success=True` 虚报成功工作
   （产生不应有的计费信用），或注入 `success=False` 压制计费。

本迭代以 TDD 方式封堵两项，并保持向后兼容。

## 交付物

### 变更 1：计量来源绑定（caller_did）

**`src/maref/federation/metering.py`**：
- `TaskMetric` 增加 `caller_did: str = ""` 字段，`to_dict()` 透出（roundtrip 可恢复）。
- `record()` 增加 `caller_did: str = ""` 可选参数（放签名末尾，既有调用零改动）。
- SQLite 持久化：`task_metrics` 表新增 `caller_did TEXT NOT NULL DEFAULT ''` 列；
  `_persist` 写入、`_load_from_disk` 读取（旧库无此列时回退 `""`，用 `row.get` + mypy ignore）。

### 变更 2：success 由执行器实测定（禁止 params 注入）

**`src/maref/orchestration/federated_plan_executor.py`**：
- `_dispatch_step` 移除 `success = bool(params.get("success", True))`（调用方可注入点）。
- 计量记录 `success=record.success` —— 由执行器从 `dispatch_result is not None` 实测定
  （`record.success` 仅在 gateway 返回非 None 时置 True，其余路径保持 False）。
- 计量同时绑定 `caller_did=consumer_org`（请求方即调用方身份）。

### fail-open 复现与封堵

- **复现**：plan params 携带 `"success": False` → 计量记录 success=False（恶意压低计费信用）；
  或携带 `"success": True` + 实际派发失败（无 agent/无结果）→ 若执行器提前返回则无计量，
  但若派发成功路径则成功由 params 决定。
- **封堵**：success 不再从 params 读取，完全由 `dispatch_result` 实测定；计量绑定 caller_did
  提供来源可追溯性。

## 设计决策

| 决策 | 理由 |
|------|------|
| `caller_did` 可选参数默认 "" | 向后兼容——既有 record() 调用（含 SQLite 持久化测试）零改动 |
| caller_did 语义 = 请求方（consumer_org） | 联邦计量中 consumer 是任务请求方；提供方由 provider_org 表达 |
| success 从 `record.success` 读取而非独立变量 | 单一事实来源，杜绝「params 注入值」与「执行器判断值」分叉 |
| SQLite 列 DEFAULT '' + 读取时兜底 | 旧库文件无需迁移即可加载（缺列时回退空字符串） |
| `row.get` + `# type: ignore[attr-defined]` | ruff（SIM401 建议 .get）与 mypy（sqlite3.Row stub 无 .get）冲突时的折中 |
