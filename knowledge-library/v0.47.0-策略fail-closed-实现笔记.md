# v0.47.0 S3 策略 fail-closed 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P0 第三项 —— 策略 fail-closed（默认 DENY + ad-hoc 降级）

## 概述

v0.46.1 深度审计定位 `federation/policy.py` 两处 fail-open：
1. **无规则匹配默认 ALLOW** —— 未注册规则的 action 一律放行（open by default）；
2. **ad-hoc 层无条件最高优先** —— 任意 ad-hoc 规则（如合规例外）无论优先级一律压过联邦层规则，
   可被低优先级的宽松 ad-hoc 规则覆盖联邦级 DENY。

本迭代以 TDD 方式将引擎改为 fail-closed 语义。

## 交付物

### 变更 1：默认 DENY + `no_rule_match` 审计标记

**`src/maref/federation/policy.py`**：
- `PolicyEvaluationResult` 新增 `no_rule_match: bool = False` 字段，`to_dict()` 输出该标记
  （供调用方记录 `E1006`/`no_rule_match` 类审计事件）。
- `evaluate()` 无任何匹配规则时：`PolicyDecision.ALLOW` → `PolicyDecision.DENY`，
  `no_rule_match=True`。

### 变更 2：ad-hoc 层降为与 federation 层同优先级

**`src/maref/federation/policy.py`**：
- `evaluate()` 中 `adhoc_matches` 并入 `fed_matches`（同一优先级层），
  取消「adhoc 非空即返回」的无条件覆盖分支。
- 新增模块级 `_RESTRICTIVENESS` 常量（DENY=3 / DEFER=2 / ALLOW=1 / NOT_APPLICABLE=0）。
- `_highest_priority()` 决胜键由 `(priority, rule_id)` 改为 `(priority, restrictiveness, rule_id)`：
  同 priority 时按更严格决策决胜（fail-closed）。
- `_resolve_conflict()` 的 MOST_RESTRICTIVE 分支复用 `_RESTRICTIVENESS` 常量（消除重复定义）。

### 变更 3：jurisdiction 层隐性 fail-open 消除（S3 安全原则延伸）

**`src/maref/federation/jurisdiction_router.py`**：
- `JurisdictionConfig.default_decision` 由 `PolicyDecision.ALLOW` → `PolicyDecision.DENY`。
  规划 S3 落点为 `policy.py` + `jurisdiction_rules.py`，`default_decision=ALLOW` 是 jurisdiction
  引擎（engine 为 None 时）的独立 fail-open 点；按规划 §5.2「不确定时拒绝而非放行」原则一并封堵。

### fail-open 复现与封堵

- **复现**：`FederationPolicyEngine().evaluate("any_action")` 返回 ALLOW（无规则即放行）；
  联邦 DENY 规则 + 同级 ad-hoc ALLOW 规则 → ad-hoc 无条件胜出。
- **封堵**：无匹配 → DENY + `no_rule_match` 标记；ad-hoc 并入 federation 层按 priority 竞争，
  平局按 restrictiveness 严格决胜。

## 设计决策

| 决策 | 理由 |
|------|------|
| `no_rule_match` 放在结果对象而非单独事件 | 调用方（saga orchestrator / jurisdiction router）零改动即可消费；to_dict 直通审计 |
| ad-hoc 并入 federation 层而非单列平局表 | 规划明确「降为与 federation 层同优先级」；`_resolve_conflict` 的冲突策略逻辑无需改动 |
| `_highest_priority` 加 restrictiveness 键 | 平局时 fail-closed（DENY 胜 ALLOW），确定性由 rule_id 兜底 |
| `JurisdictionConfig.default_decision` → DENY | 消除 jurisdiction 层 engine 缺失时的隐性放行；与 policy 引擎 fail-closed 语义一致 |
| 既有测试同步更新而非新增「旧行为回归」 | S3 是明确的行为契约变更；保留旧断言将掩盖漏洞 |
