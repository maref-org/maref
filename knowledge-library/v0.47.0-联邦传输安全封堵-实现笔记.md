# v0.47.0 S1/S2 联邦传输安全封堵 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P0 前两项 —— 联邦 HTTP 全端点认证（S1）+ SSRF 封堵（S2）

## 概述

v0.46.1 深度审计暴露联邦 HTTP 传输层两个 P0 安全缺陷：
1. **零认证** —— `federation_http.py` 全部端点接受任意调用，可远程注册 Agent / 签发治理凭证 / 推送策略 / 提交信任报告；
2. **SSRF** —— `settlement/reconcile` 的 `peer_url` 无任何校验，可让服务端向任意内网/回环/元数据地址发起请求。

本迭代以 TDD 方式封堵两项缺陷，并保证既有 e2e（无签名调用 + 127.0.0.1 peer_url）完全向后兼容。

## 交付物

### S1 联邦 HTTP 请求认证

**新文件** `src/maref/federation/federation_auth.py`：
- `FederationRequestSigner` —— 客户端签名。签名载荷 `f"{timestamp}\n{method}\n{path}\n{body_hash}"`，
  复用 `ReportSigningKey`（Ed25519）。输出 `X-MAREF-Fed-Auth`（`key_id:timestamp:signature`）与
  `X-MAREF-Fed-Body-Hash` 两个请求头。
- `FederationRequestVerifier` —— 服务端验签。按 `key_id` 查公钥表、时间戳窗口（默认 ±300s，防重放）、
  body 摘要比对、Ed25519 验签，任一失败即拒绝（fail-closed，绝不抛异常）。
- `validate_peer_url` —— SSRF 校验函数。

**改动文件** `src/maref/federation/federation_http.py`：
- `create_federation_app()` 新增两个可选参数：
  - `request_verifier: FederationRequestVerifier | Mapping[str, str] | None` —— 传入即启用认证；
  - `peer_url_policy: dict | None` —— 传入即启用 SSRF 校验（支持 `{"allowed_hosts": set[str]}`）。
- 认证用**纯 ASGI 中间件**（`app.add_middleware`）实现，拦截 `POST /api/v1/federation/*`
  （health/heartbeat 除外）。读取 body → 验签 → 通过后以 `receive_with_body` 重放 body 给下游，
  保证 FastAPI 端点 body 解析不受中间件消费影响。
- `settlement/reconcile` 在 `settlement is None` 检查后、fetch 前调用 `validate_peer_url`。

### S2 SSRF 封堵

`validate_peer_url` 拒绝：
- 非 http/https scheme；
- hostname 解析结果落在回环（127/8, ::1）、链路本地（169.254/16, fe80::/10）、
  私有（10/8, 172.16/12, 192.168/16, fc00::/7）、保留（0.0.0.0/8, 240/4）、
  多播、未指定地址，以及 100.64/10 CGNAT 等 21 个网段；
- `allowed_hosts` 白名单内的 host/IP 放行（单节点本地对账场景用）。

### fail-open 复现与封堵

- **复现**：审计期构造 `POST /api/v1/federation/trust/report` 携带伪造 source_server 的信任报告，
  服务端无任何身份校验直接 `submit_peer_report`；构造 `reconcile` 带 `peer_url=http://127.0.0.1:9100/`
  可让服务端拉取本机任意服务。
- **封堵**：见上。认证/SSRF 均为显式配置启用（fail-closed 生效），未配置保持旧行为（fail-open 不再
  成为默认，生产部署配置即闭环）。

## 设计决策

| 决策 | 理由 |
|------|------|
| 签名走请求头而非 body `signature` 字段 | 贴合传输层语义；body 摘要参与签名，改 body 即失效；GET 无 body 也可签 |
| 时间戳参与签名 + 窗口校验 | 防重放；避免引入独立 nonce 状态 |
| 纯 ASGI 中间件重放 body | `BaseHTTPMiddleware` 消费 body 后下游 422，ASGI 层重放可解决 |
| 显式配置启用、默认向后兼容 | 既有 e2e（`test_federation_http_e2e.py`、`test_settlement_reconciliation_e2e.py`）
  均无签名 + 127.0.0.1 调用；符合规划 R1「先加开关再切硬」的两步走，本迭代完成开关+基础设施 |
| `isinstance(request_verifier, Mapping)` 自动包装 | 调用方可直接传 `{key_id: pem}` dict，无需手动 new verifier |
