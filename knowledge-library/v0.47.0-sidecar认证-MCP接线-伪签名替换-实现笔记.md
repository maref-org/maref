## S6 — sidecar 认证 fail-open 修复

### 现状与缺陷

`api_auth.py` 三处 fail-open：
1. `_verify_token` 无 key 时 `return True`（line 108）——未配置 `MAREF_API_KEY` 时一切放行；
2. `_has_scope` 恒 `return True`（line 118）——scope 声明形同虚设；
3. `_AUTH_BYPASS_PATHS` 含 `/_debug/`——调试端点整段绕过认证。

另有一个隐蔽缺陷：`_register_route_scope` 注册的是 FastAPI 路径模板
（`/api/v1/hitl/{event_id}/approve`），而 middleware 用 `request.url.path`（具体 URL）查
`_SCOPE_MAP`，两者永不匹配 → 参数化路由的 scope 检查从不生效。

### 修复

- `_verify_token`：无 key 时返回 False（fail-closed）。
- `AuthMiddleware` 增加 `allow_unauthenticated: bool = False` 构造参数；无 key 时该旗标为 True
  才放行（显式开发模式），否则 401/403。`server.create_app`/`SidecarFastAPI` 透传该参数，
  默认读取 `MAREF_ALLOW_UNAUTHENTICATED` 环境变量（生产 fail-closed，测试/开发显式开启）。
- `_has_scope`：读取 `MAREF_API_KEY_SCOPES`（逗号分隔）；配置后 master key 仅拥有列出的 scope，
  未配置保持全 scope（历史主密钥模型）。
- `_AUTH_BYPASS_PATHS` 移除 `/_debug/`。
- 新增 `_resolve_required_scope(path)`：先精确匹配，再用正则把 `{param}` 模板转 `[^/]+` 匹配
  参数化路由（修复 scope 失效缺陷）。
- `APIKeyManager.reload()` 同步重置 `_ALLOWED_SCOPES`。

### fail-open 复现与封堵

- **复现**：`MAREF_API_KEY` 未配置时任意 Bearer token 访问受保护端点返回 200；
  `/_debug/health` 无 token 直接 200；`/api/v1/hitl/{id}/approve` 的 `hitl:write` scope 从不校验。
- **封堵**：无 key → 拒绝；`/_debug/` 需认证；参数化路由 scope 真实校验。

## S7 — /api/mcp 接入 MCPGateway 三层治理

### 现状与缺陷

`/api/mcp` 的 `tools/call` 直接调 `mcp_bridge.handle_tool_call`，绕过
`/api/mcp/gateway/tools/call` 走的三层治理（SecurityGate→PolicyEngine→CircuitBreaker），
攻击者经标准 MCP 端点可跳过所有 MCP 安全门。

### 修复

- `server.py` `/api/mcp` `tools/call` 分支改为 `gateway.route_tool_call(tool_name, arguments)`，
  结果包装为 JSON-RPC `result`（与 gateway 端点统一）。
- `_setup_routes` 新增 `_wire_mcp_governance(gateway)`：注入 `MCPSecurityGate` +
  `MCPPolicyEngine` + `MCPGovernance(CircuitBreaker)`。
- `/api/mcp/.well-known` 补 `version` 字段（MCP 规范，取 `SUPPORTED_PROTOCOL_VERSIONS` 最新）。

### fail-open 复现与封堵

- **复现**：`/api/mcp` tools/call 调用被 block 的 shell/exec 工具直接执行（无安全门）。
- **封堵**：tools/call 统一走 `route_tool_call` 三层治理。

## S8 — 三处伪签名替换为 Ed25519

### 现状与缺陷

1. `protocol_bridge.py:404` `verify_and_convert_mcp_to_a2a` 用
   `hashlib.sha256(f"{agent_did}:{message_id}")` 计算"签名"并比较——知道 DID+message_id 即可伪造；
2. `a2a_secure_transport.sign_payload` 用 TLS 私钥前 32 字节作 HMAC 密钥——不是标准签名，
   且泄露 TLS 私钥即泄露签名密钥；
3. `mcp_security.OAuthMiddleware._validate_token` 只 base64 解码 JWT payload 不验签——
   任意伪造 token 通过。

### 修复

1. `SecureProtocolBridge.__init__(peer_public_keys, signing_key)`：`verify_and_convert_mcp_to_a2a`
   用 `agent_did` 查公钥表做 `ReportSigningKey.verify_signature`；payload 仍为
   `{agent_did}:{message_id}`；重放保护保留。
2. `A2ASecureTransport.sign_payload`：新增 `signing_key: ReportSigningKey | None` 参数，
   有 key 时 Ed25519 签名，否则返回 ""（不再截断 TLS 私钥）；新增 `verify_payload_signature`。
3. `OAuthMiddleware` 增加 `verification_key: bytes | None`；`_validate_token` 在配置 key 时
   用 HMAC-SHA256 验签（比对 `signing_input` 的 HMAC 与签名），失败抛 `PermissionError`；
   未配置 key 保持仅解码（向后兼容，但配置即强制验签）。

### fail-open 复现与封堵

- **复现**：`sha256(f"{did}:{msg_id}")` 可被任何知晓者伪造；HMAC 私钥截断泄漏真实私钥；
  JWT 篡改 payload 后签名未校验仍通过。
- **封堵**：三处全部改为标准 Ed25519 / HMAC 验签，伪造/篡改被拒。

## Review 补强（P0 全量 code review 后）

对 S1–S8 全部改动做交叉审查（双 agent：调用方兼容性 + 规划验收对照），发现并修复以下问题：

1. **S1 客户端签名缺失**（规划明确要求 "FederationHTTPClient 请求签名"）：给
   `FederationHTTPClient` 增加 `signer` 参数，经 httpx `event_hooks["request"]` 自动为 POST
   加 `X-MAREF-Fed-*` 签名头（`_sign_request`）；新增测试验证钩子生成的 header 被服务端 verifier
   接受（含真实 ASGI 端到端）。
2. **S1 无 `auth_failed` 审计**（专项验收要求"拒绝并产生 auth_failed 审计"）：中间件拒绝时调用
   `_record_auth_failed`（模块级 `_AUTH_FAILED_LOG` + `get_auth_failed_log()`），记录
   path/method/reason/key_id；新增 2 项审计测试。
3. **S3 连锁影响**：`tests/federation-e2e/test_federation_saga_e2e.py::test_three_process_federation_saga`
   的 initiator 无 policy 规则 → fail-closed 后 saga 全 DENY 失败。修复：initiator 显式加
   `delegate_to_executor`/`assess_trust`/`execute_task` 三个 ALLOW 规则；同步
   `federated_saga_orchestrator.py` 两处 docstring（"无规则默认 DENY"）消除与实现矛盾。
4. **S7 测试用 mock 未验证真实拦截**：补 `test_real_security_gate_blocks_dangerous_tool` 端到端
   测试（`maref_exec` 经 `/api/mcp` 被 SecurityGate 真实拒绝）。
5. **S8 `MCPSecurityGate.authenticate_request` 仍不验签**：补 `verification_key` 字段 + HS256 验签
   （与 `OAuthMiddleware` 对齐，配置 key 时强制）。
6. **`tests/maref/integration/conftest.py` 全局污染**：该 conftest 把 `a2a_secure_transport`
   stub 成 MagicMock 到 `sys.modules`，污染整个 session（任何测试组合跑 `tests/maref/` 后 a2a
   变 mock）。经验证该模块已无循环导入依赖（真实 import OK），从 `_STUB_MODULES` 移除；
   验证 `tests/maref/integration/` 无新增失败（仅 1 项 `test_mcp_hitl_bridge::test_to_dict`
   为基线已存在的失败）。
