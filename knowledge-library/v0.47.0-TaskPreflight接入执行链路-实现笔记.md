# v0.47.0 S11 TaskPreflight 接入执行链路 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P1 第三项 —— 任务级预检接入 UnifiedHarness 执行链路

## 概述

v0.46.1 深度审计定位：**TaskPreflight 2.0（v0.44 已实现，6 项检查含风险授权）是孤岛**——
`execution/harness/unified.py` 的 `preflight()` 只做生命周期转换 + governance 检查 + hook 触发，
从不执行 TaskPreflight。任务级预检门禁在生产执行链路中零调用。

本迭代把 TaskPreflight 接入 `UnifiedHarness.preflight()`，且风险授权由软判定升级为硬门禁
（fail-closed）。

## 交付物

### `src/maref/execution/harness/unified.py`

- `UnifiedHarness.__init__` 新增 `task_preflight: Any | None = None` 参数（鸭子类型注入）。
- `preflight(context: dict[str, Any] | None = None)`：
  - 注入 `task_preflight` 时执行 `execute(context)`；
  - `passed=False` → lifecycle → FAILED，抛 `HarnessAbortedError`（fail-closed，含被阻断的 check 名）；
  - `passed=True` → 结果摘要追加到 warnings，过渡 READY。
- 新增 `last_preflight` 属性暴露最近一次 TaskPreflight 结果（审计/运维查询）。
- 未注入 `task_preflight` → 行为完全不变（向后兼容，既有 37 项 harness 测试零改动）。

### 风险授权硬门禁（规划 S11 第二部分）

`RiskAuthorizationCheck`（task_preflight.py，v0.44 已实现）当前即硬门禁语义：HIGH/IRREVERSIBLE
越界 → `PreflightCheckStatus.FAIL` + `details["action_required"]="HITL"`。S11 通过 harness 装配使
该 FAIL 真正阻断执行（此前软判定仅返回 WARN/结果不阻断）。新增测试锁定该硬门禁行为。

## 设计决策

| 决策 | 理由 |
|------|------|
| `task_preflight` 参数可注入、默认 None | 与 S9/S10 一致"显式配置启用、默认兼容"；既有 harness 测试零改动 |
| `preflight(context)` 带 context | TaskPreflight 需要 agent 规划期证据（readme/git/alternatives/decision） |
| FAIL → HarnessAbortedError + lifecycle FAILED | fail-closed 硬门禁；调用方可捕获并展示阻断检查 |
| `last_preflight` 属性 | 运维可查询最近预检结果，不破坏返回类型（仍返回 warnings list） |
| 鸭子类型注入 | unified.py 不硬依赖 task_preflight 模块，解耦 |
