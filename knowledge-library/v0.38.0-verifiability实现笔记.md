日期: 2026-07-28

## 概述

v0.38.0 在 v0.37.0 Integrity 的基础上，将审计签名从 HMAC-SHA256 升级为 Ed25519，
并构建了完整的联邦审计体系（offline-verifiable proof、跨副本对账、REST API）。
总计 13 个特性（V1-V13），768 个治理/联邦审计测试全部通过，零回归。

## V1: AuditLogger Ed25519 迁移

### 文件
- `src/maref/governance/audit.py`

### 变更
- `AuditEntry`: 新增 `ed25519_signature`, `signer_fingerprint` 字段, `signature_type` 属性
- `AuditLogger.__init__()`: 接受 `ed25519_keypair` + `chain_integrator` 参数
- `_sign_entry()`: Ed25519 优先, HMAC 回退
- `verify_integrity()`: 自动检测签名类型
- 向后兼容: HMAC 旧日志可读
- `MAREF_ED25519_PRIVATE_KEY` 环境变量

### 设计决策
- Ed25519 over RSA: 签名小(64B), 速度快, 密钥生成简单
- 不强制迁移: 旧 HMAC 日志保持可读可验证
- signer_fingerprint 为公钥 SHA256, 用于离线场景识别签名者身份

## V3: `maref audit verify` CLI

### 文件
- `src/maref_lite/cli.py`

### 用法
```bash
maref audit verify --file audit.jsonl --pubkey signer.pem
```

### 功能
- 检查 Ed25519 和 HMAC 签名
- 链 hash 连续性验证
- 输出结构化报告（总条目/有效/篡改）

## V4: `maref audit export` CLI

### 用法
```bash
maref audit export --file audit.jsonl --output audit-export.json
```

### 输出
自包含 JSON 包：条目 + 签名 + 版本元数据，可用于第三方离线审计。

## V5: FederatedProof 序列化 + Ed25519 签名

### 文件
- `src/maref/eivl/federated_merkle.py`

### 新增 API
- `FederatedProof.from_dict()` / `to_dict()` / `to_json()` / `from_json()`
- `to_file()` / `from_file()` — JSON 文件持久化
- `sign(Ed25519KeyPair)` — 用 Ed25519 签发 proof

### 功能

## V7: AuditReconciler 跨副本审计对账

### 文件
- `src/maref/eivl/audit_reconciler.py` (新文件)

### 设计
- 按 position 对比副本审计日志
- 内容指纹: sha256(event_type|actor|action|details), 排除随机 ID 和时间戳
- 严重度分级:
  - critical: content_mismatch (不同内容在同一位置), entry_count_mismatch
  - info: chain_hash_mismatch (独立副本链 hash 必然不同), signature_mismatch

### ReconciliationReport
- 可序列化为 dict/JSON
- 包含每个副本的摘要和所有 discrepancy 详情

## V12: reconcile-daemon Webhook 报警

### 用法
```bash
maref federated reconcile-daemon node-a=/logs/a.jsonl node-b=/logs/b.jsonl \
  -w https://hooks.example.com/alert --webhook-interval 300
```

### Webhook 负载
```json
{
  "event": "reconcile_discrepancy",
  "timestamp": 1234567890.0,
  "replicas": ["node-a", "node-b"],
  "entry_counts": {"node-a": 100, "node-b": 100},
  "critical_count": 1,
  "discrepancies": [...]
}
```

### 防洪
- `--webhook-interval` 控制最小报警间隔
- 仅对 critical 级别 discrepancy 触发

## 架构图 (简化)

```
AuditLogger (Ed25519)
  ├── audit.jsonl (entries with signatures)
  ├── → MerkleAuditor (Merkle tree)
  │     └── → AuditChainIntegrator (chain hash continuity)
  └── → maref audit verify CLI
  └── → maref audit export CLI

FederatedMerkleAggregator
  ├── org roots (submitted via CLI or REST API)
  ├── FederatedProof (offline-verifiable inclusion proof)
  │     ├── Ed25519 signed
  │     └── → maref federated verify CLI
  └── JSON state persistence

AuditReconciler
  ├── position-based content fingerprint comparison
  ├── severity classification (critical / info)
  └── → reconcile-daemon (continuous loop)
        └── → Webhook alert (critical discrepancies)
```

## 注意事项

### 向后兼容
- HMAC 签名日志可读写, 与 Ed25519 条目共存
- 旧版 `AuditLogger(hmac_key="...")` 仍可用
- `SecurityAuditChain` 保持原 HMAC-only 行为

### 安全考虑
- Ed25519 私钥通过 `MAREF_ED25519_PRIVATE_KEY` 环境变量或 `Ed25519KeyPair` 传入
- 从不硬编码密钥
- proof 签名可独立验证, 无需访问聚合器

### 已知限制
- `read_all()` 无 limit 时对大型日志可能 OOM (已有 WARNING)
- 联邦状态文件无锁, 不适合高并发写入
- reconcile-daemon 为单机模式, 不支持分布式调度
