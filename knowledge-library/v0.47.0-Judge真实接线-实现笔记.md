# v0.47.0 S13 Agent-as-a-Judge 真实接线 实现笔记

日期: 2026-08-03
版本: v0.47.0-dev（基线 v0.46.1）
范围: v0.47 P1 第五项 —— Judge 真实接线（P1 单 Agent 接线收官）

## 概述

v0.46.1 深度审计定位：**RuleJudge（方案 C 已实现）在 loop 层未真实接线**——
`ConvergentLoop._evaluate` 对 `VerifierConsensus` 提交的是普通 dict，`_call_verifier` 的
`isinstance(item, Trace)` 恒 False → 走向后兼容的仿真表决，Judge 永不触发。同时
`VerifierConsensus` 无 `record_call`，Trace 裁决后不回写 accuracy 校准。

本迭代完成 Judge 真实接线 + accuracy 回写闭环，P1 单 Agent 接线（S9–S13）收官。

## 交付物

### `src/maref/governance/verifier_consensus.py`

- 新增 `record_call(name, correct)`：Trace 裁决后回写 verifier accuracy 校准
  （委托 `VerifierRegistry.record_evaluation`），未知 verifier 静默忽略。
- 新增 `judges` 属性（只读视图）。

### `src/maref/integration/maref_loop_adapter.py`

- `MAREFLoop.__init__` 装配 `RuleJudge` 到 consensus
  （`judges={"judge": RuleJudge()}`）——轨迹输入走真实仲裁而非仿真表决。

### `src/maref/loop/convergent.py`

- `_evaluate` 当 evaluator 是 `VerifierConsensus` 且 `has_judges()` 时，把输出构造为
  `Trace`（含一步 TraceStep，action=输出摘要）提交 → 走真实仲裁；否则保持 dict 仿真
  向后兼容（未装配 judge 的既有调用零改动）。

### `tests/governance/test_pipeline_trust_boundary.py`（S9 测试修复）

- `test_legacy_security_trust_boundary_deprecated` 改用 `importlib.reload` 重触发
  DeprecationWarning——修复组合测试时模块已被 `loop/bridge.py` 缓存 import 导致警告不重复
  触发的隔离问题。

## 设计决策

| 决策 | 理由 |
|------|------|
| `record_call` 委托 registry.record_evaluation | 复用既有精度统计逻辑（precision 计算），一处实现 |
| `MAREFLoop` 装配 RuleJudge | 满足规划"装配 RuleJudge"；`MAREFLoop.check` 的 dict 路径保持仿真（向后兼容），Trace 路径走真实仲裁 |
| `ConvergentLoop` 仅 `has_judges()` 时构造 Trace | 未装配 judge 时零行为变化（既有 loop 测试零改动）；装配后真实仲裁 |
| Trace 一步（action=输出摘要） | 收敛循环每轮评估一次输出，构造单步轨迹足够触发 judge 模式检查 |
| S9 测试 reload 修复 | 消除 import 缓存导致的测试顺序敏感 |
