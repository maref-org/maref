## 1. 发布范围

v0.55.1 之后的补丁版，只修复 CI 门禁的假信号，不含功能变更、架构调整或依赖升级：

1. `scripts/check_openclaw_compat.py` 新增 `3 = 检查源不可用（skipped）` 语义。`maref-governance/` 是 `.gitignore` 排除的外部项目目录（`.gitignore:175`），干净 checkout 下必然缺失；旧逻辑将其判为 `2 = breaking`，导致每日定时 workflow 必然失败。
2. `.github/workflows/openclaw-compat-check.yml` 改用 `set +e` 捕获退出码。旧逻辑在 `bash -e` 下脚本非零退出即终止，`echo "exit_code=$?" >> $GITHUB_OUTPUT` 永不执行，下游 `steps.compat.outputs.exit_code == '2'` 永远为假——真正的 breaking change 不会创建告警 Issue。
3. 将 breaking 判定移到末尾独立 gate 步骤，使 Issue 创建与 Summary 在失败前仍可执行；`Summary` 显式区分 `0/1/2/3`。

明确排除：功能新增、Python/依赖版本变更、Tauri 桌面产物、容器镜像发布。

### 兼容性影响

- 退出码契约扩展：`3` 表示“本次无法检查”，消费方不得将其解释为 breaking。既有 `0/1/2` 语义不变。
- 正常完整 checkout 行为不变（本地实测仍为 `0 = COMPATIBLE`）。
