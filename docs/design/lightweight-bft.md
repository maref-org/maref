> **状态**: 预研报告（2026 年仅设计不生产化；v0.48.0-M1 评审）。

## 1. 目标与范围

评估适用于 **<20 节点** 联邦的轻量级拜占庭容错（BFT）共识，作为 Level 2 联邦裁决
（联邦制宪法第三章）的底层投票机制。

- **范围**: 常规联邦裁决（非红线）共识；
- **排除**: 大规模 BFT（≥20 节点，2028 共识年目标）、PBFT 全实现；
- **前置**: 成员身份已认证（F2 成员表 + Ed25519 票面签名）。

## 2. 协议设计

### 2.1 三阶段流程（对齐 TP-08 §2.6）

```
propose → pre-prepare → prepare → commit
```

1. **propose**: 提议方（proposer，本轮 leader）广播区块/提案；
2. **pre-prepare**: 各成员收到提案，校验签名 + 内容合法性，广播 pre-prepare；
3. **prepare**: 成员收集 ≥2f+1（f=容忍故障数）pre-prepare，广播 prepare；
4. **commit**: 收集 ≥2f+1 prepare，本地 commit，广播 commit；
5. **finalize**: 收到 ≥2f+1 commit 即最终确认。

> f = (N-1)/3，N<20 时 f≤6。N=4 时 f=1，需 ≥3 成员确认。

### 2.2 与现有 MAREF_Consensus.tla 的关系

现有 `MAREF_Consensus.tla` 形式化**多数 quorum 表决**（v0.47 F2 实现）。
轻量级 BFT 是其在拜占庭容错下的**强化**：
- 相同: 成员身份认证（F2）、Ed25519 签名票面；
- 差异: quorum 从"简单多数"升级为"≥2f+1（容忍 f 恶意）"，引入 prepare/commit 两阶段确认。

### 2.3 提议者轮换

- 每轮 leader 按成员 DID 排序轮换（防单点长期控制）；
- leader 故障（超时无有效提案）→ 视图切换（view change）→ 下一 leader。

## 3. TLA+ 不变量（预研草案）

基于 `MAREF_Consensus.tla` 扩展，建议验证以下不变量：

| 不变量 | 语义 |
|--------|------|
| **Agreement** | 无两个诚实成员对同一提案得出不同最终决策 |
| **Validity** | 最终决策值必须是某诚实成员提出的合法值 |
| **Termination** | 在 ≤f 恶意节点下，提案最终被确认或超时废弃 |
| **Integrity** | 无成员对同一提案投两次票（对齐 F2 voter_ids 去重） |
| **Authenticity** | 只有成员身份认证的票面进入计数（F2 成员表） |
| **Byzantine-Fault-Tolerance** | 容忍 ≤f 恶意节点（经典 BFT 下界 f=(N-1)/3） |

> 预研结论: 上述不变量与 `MAREF_Consensus.tla` 现有关键性质（多数、去重、认证）
> 兼容，生产化时在 `src/formal/` 新增 `MAREF_LightweightBFT.tla` 并跑 TLC。

## 4. 性能与资源预估（<20 节点）

| 指标 | 预估值 |
|------|--------|
| 消息复杂度 | O(N²)（每阶段全广播） |
| 延迟 | N=10 时 <500ms（内网） |
| 吞吐 | 常规裁决 50~100 提案/s |
| 存储 | 提案+签名 入分布式审计总线（L3），~1KB/提案 |

## 5. 与联邦制宪法（L1）的衔接

- 常规裁决: 轻量级 BFT ≥2f+1 确认（对应 L1 3.3.1 的 2/3 多数——f=1 时 2f+1=3 = 4 节点的 3/4，近似）；
- 红线裁决（FR-001~FR-004）: 保留 3/4 超级多数 + 人类否决（L1 3.3.2），BFT 仅作常规路径；
- 修订: 3/4 超级多数（L1 4.2）独立于 BFT（修订是慢路径）。

## 6. 开放问题

- O1: BFT 确认阈值与宪法多数（2/3 vs 3/4）的精确映射；
- O2: 视图切换在 <20 节点下的实现复杂度；
- O3: 与 F4 持久化的交互（提案落 SQLite 后如何参与共识）。

## 7. 预研结论

**可行性: 高**。轻量级 BFT 在 <20 节点联邦上是现有 `MAREF_Consensus.tla` 共识的
自然强化，复用 F2 成员认证 + Ed25519 签名 + F4 持久化基础设施。生产化（v0.49+）需:
新增 `MAREF_LightweightBFT.tla` 形式化 + TLC 验证 6 条不变量，再实现。
