# MAREF Gossip 协议同步设计

> **地位**: Level 2 架构设计（v0.48.0 L5）。
> **对应任务**: TP-08 T8.5。
> **状态**: 设计文档（2026 年仅设计不生产化；v0.48.0-M1 评审）。
> **前置**: 联合状态机（L2）成员状态需跨组织同步。

---

## 1. 设计目标

为 Level 2 联邦提供**无中心**的成员状态 / 审计事件传播：

1. 成员状态（L2 快照）经 Gossip 传播，联邦态在有限周期内收敛；
2. 分布式审计总线（L3）事件经 Gossip 广播，全体成员可校验；
3. 支持 `N` 成员规模（TP-08：100 Agent 同步 ≤30s）。

## 2. 协议模型

### 2.1 消息

```json
{
  "kind": "state_snapshot" | "audit_event" | "constitution_amendment",
  "payload": {},
  "generation": 42,
  "origin_org": "did:maref:org:acme:7f3a",
  "timestamp": 1785753600.0,
  "signature": "ed25519-hex",
  "signer": "org-key-fingerprint"
}
```

### 2.2 传播

- **随机选择**: 每周期随机选 k 个 peer 转发（k = 3~5，对齐 TP-08 §2.5）；
- **去重**: `(kind, origin_org, generation)` 作为消息 ID，收到即去重；
- **TTL**: 消息存活 N 跳（默认 6），防无限传播。

### 2.3 合并（CRDT 语义）

- 成员状态快照以 `generation` 版本合并：高 generation 覆盖低；
- 审计事件仅追加（不可覆盖，对齐宪法 FR-003）；
- 冲突（同 generation 不同内容）：取签名有效且时间戳较新者，记入审计总线。

## 3. 收敛性

- **Theorem（启发式）**: 在 k≥3 随机转发 + 去重下，N 成员联邦的消息覆盖率
  在 O(log N) 轮内达到全体；100 成员 ≤30s（假设周期 300ms）满足 TP-08 目标。
- **失败容忍**: 单节点故障不阻断传播（冗余路径）。

## 4. 防伪与完整性

- 每条消息 Ed25519 签名（对齐 F2 成员密钥）；
- 接收方校验签名 + S1 传输认证；
- 合并结果入分布式审计总线（L3）可复核。

## 5. 与现有组件的衔接

| 组件 | 衔接 |
|------|------|
| 联邦发现（discovery.py） | peer 表可作为 Gossip 初始邻居 |
| 成员管理（membership.py） | 心跳/健康度联动 Gossip 邻居选择 |
| 联邦传输（S1） | Gossip 消息经 S1 签名认证传输 |
| 审计总线（L3） | 审计事件经 Gossip 广播 |

## 6. 开放问题

- O1: k 值自适应（按联邦规模）；
- O2: 分区（network partition）下的收敛保证（需 CRDT 状态合并细化）；
- O3: 与联邦心跳（membership）的邻居健康度耦合。
