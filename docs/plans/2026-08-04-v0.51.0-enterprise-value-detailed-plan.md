## 1. 版本主题与范围

**主题**: 把治理从「防止 Agent 做错事」延伸到「证明 Agent 创造了多少业务价值」——补齐飞轮两端（数据接入治理 + ROI/结果度量）与三重失控硬伤（数据泄露、人对 AI、AI 自身）。

**范围**: A1-A3 数据接入治理 + B1-B3 价值度量 + C1-C3 数据泄露防护 + D1-D2 可解释性 + E1-E2 grounding。共 13 个交付物。

**不做的（推迟）**: A4/A5（质量评分/drift 业务通道）、B4/B5（ROI 报告/RaaS 结算）、C4（跨域分类拦截）、D3（置信度挂钩）、E3/E4（回退策略/通用幻觉检测）、F1-F5（工程化落地）——列入 v0.52+ 候选。

## 4. 验收标准

| 维度 | 验收 |
|------|------|
| 数据接入 | 企业数据源可登记分类分级；`trace_downstream` 返回扩散面；schema 变更触发告警 |
| 价值度量 | 任务可附加 `ValueMetric`；结算公式含 `outcome_quality`；`aggregate` 按 agent/team/org 返回 |
| 数据泄露 | 字段按分类自动消毒、授权可还原；敏感数据跨域流动可追踪、越界触发熔断 |
| 可解释性 | 每个决策产出结构化推理链（mandatory 模式缺省抛错）；HITL 审批前可见 explanation |
| 幻觉 | grounding 忠实度评分可算；第五协议可三角验证 |
| 质量 | 新增模块 ≥90% 分支覆盖；全仓 ≥50%；ruff/mypy 0 errors（不含第三方）；新增测试全绿；v0.50 基线通过数不降级 |

## 7. 执行纪律

每个 S 交付物：
1. 先写失败测试（`tests/<域>/test_*.py`）
2. 运行确认失败（`pytest tests/<path> -v`）
3. 写最小实现
4. 运行确认通过
5. `git commit -m "feat(data): v0.51 W1-S1 DataCatalog"` / `feat(value): ...` / `security(data): ...`

提交消息遵循 AGENTS.md：`feat(module): description` / `security(module): description`。
每完成里程碑 M1-M4 更新本文件「8. 实施完成状态」并做阶段回归。
