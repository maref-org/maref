# 证据账本模板 v1.0

> 目的：把"访谈里说的话"和"可以拿出来给第三方看的事实"分开。
> 账本 `ledger.yaml` 记**访谈事实**；本文件定义**证据如何分级、如何脱敏、如何被引用**。

## 一、四级证据（只升级，不跳级）

| 级别 | 定义 | 载体 | 能否对外引用 |
|---|---|---|---|
| **L0 线索** | 一个可能的访谈对象 / 一条行业传闻 | 本地待办 | ❌ 不入库 |
| **L1 访谈记录** | 对方同意记录的 Q1–Q5 回答 | `ledger.yaml` 条目 + 录音/纪要 | ✅ 只引角色与数字，不引出处人 |
| **L2 强信号** | 报价需求、试用协议、书面会议纪要 | `artifacts/` 脱敏副本 | ✅ 引"时间 + 机构类型 + 金额区间" |
| **L3 硬信号** | 合同、发票、中标通知、付款凭证 | 不公开，本地归档 + 哈希存证 | ✅ 引"存在 + 金额区间 + 日期"，原文不出库 |

规则：
- **L2/L3 必须带日期**，否则降级为 L0。
- **只有 L1 的"愿意买"是口头意愿，不得写进任何对外材料当作需求证明。**
- 升级必须有新载体；不允许"同一份纪要既算 L2 又算 L3"。

## 二、脱敏清单（L2 入库前逐项过）

必须删除/替换：

- ☐ 姓名、职位、手机、邮箱、微信、工号
- ☐ 公司全称（改为"某省级政务 SI / 某城商行 / 某三甲医院"）
- ☐ 项目名、合同编号、甲乙方名称
- ☐ 具体金额（改为区间：`10–20 万`）
- ☐ 可反推到个人的时间地点组合

保留（这些是证据价值所在）：

- ☑ 机构类型、行业、规模区间
- ☑ 问题描述、发生时间（精确到月）
- ☑ 金额/人天区间、走了哪个预算科目
- ☑ "对方认了/不认"这一结果本身

## 三、命名与存放

```
docs/research/interviews/
├── ledger.yaml                      # 访谈事实（结构化）
├── SCRIPT.md                        # 执行脚本
├── TARGETS.md                       # 目标与漏斗
├── EVIDENCE.md                      # 本文件
└── artifacts/
    ├── README.md                    # 脱敏规则与索引
    └── INT-YYYYMMDD-NN-<kind>.md    # kind: quote | trial | minutes | contract-hash
```

- `kind` 取值：`quote`（报价需求）、`trial`（试用协议/验收标准）、`minutes`（纪要）、`contract-hash`（合同哈希与元数据，原文不入库）。
- 每个 artifact 首行必须写：`级别: L2|L3`、`日期: YYYY-MM-DD`、`脱敏: 已按 EVIDENCE.md §2 处理`。
- L3 原文（合同/发票扫描件）**不进 git**，只存本地加密目录，仓库内只放 `sha256 + 金额区间 + 日期`。

## 四、不能当证据的东西

- ❌ 自己写的 TAM/SAM 测算
- ❌ "某朋友说这个有需求"
- ❌ 展会名片、微信群人数
- ❌ 我方制作的 demo 截图
- ❌ 未标注日期的会议纪要
- ❌ 匿名问卷（无法追问，且样本自选）

## 五、与 `ledger.yaml` 的对应关系

| ledger 字段 | 证据级别要求 |
|---|---|
| `spend_cny > 0` | 至少 L1（对方口述即可，但需 consent） |
| `hours_wasted > 0` | 至少 L1 |
| `would_buy.signal = trial` | **L2**（试用协议/验收标准） |
| `would_buy.signal = quote_requested` | **L2**（书面报价请求或纪要） |
| `would_buy.signal = paid` | **L3**（合同/发票/中标通知） |

> 若某条记录声称 `paid` 但拿不出 L3，`scripts/interview_ledger.py --check` 只能校验字段完整性，
> **不能**替你判断真伪——所以对外引用前必须人工核对一次原件。
