# 切换访谈目标清单 v1.0

> 规则：**先定准入判据，再找人**。不符合判据的人聊得再热络也不入账本。
> 本文件只记机构类型与编号；姓名/联系方式留在本地（不进仓库，见 `SCRIPT.md` §0）。

## 一、五席结构（缺一不可）

| 编号 | 角色 | 为什么必须有 | 准入判据（不满足就不约） |
|---|---|---|---|
| T1–T3 | **系统集成商 / Agent 交付方** | 他们替甲方背交付责任，是治理成本的直接承担者 | 过去 12 个月交付过 ≥1 个政企 Agent / 自动化项目，且合同里有验收或安全条款 |
| T4 | **持证测评 / 审计机构** | 判断"证据链能否作为测评输入"，决定尺子有没有下游 | 有 CNAS / 等保测评 / 软件测评资质，且近 12 个月做过 AI 相关测评 |
| T5 | **受监管企业安全负责人** | 真实买方预算与问责链在这里 | 金融 / 医疗 / 能源 / 政务之一，且已上线或试点 Agent，有明确合规责任人 |

> 若 T4 明确回答"这类证据我们不认"，那么"尺子"路线在**下游**就不成立——这一条比 T1–T3 的正面反馈更重要。

## 二、筛选漏斗（每席都要走完）

```
候选池（≥3× 目标数）
  → 准入判据过滤（机构类型 + 近 12 个月事实）
  → 冷启动触达（一页纸 + 一句"我不是来卖东西的"）
  → 约 30–40 分钟
  → 填 ledger.yaml
```

**淘汰记录也要留**：被拒/不回复的候选记在下方"漏斗"表，用于判断"约不到人"到底是渠道问题还是需求不成立。

## 五、停止条件（避免无限期"再约一个"）

满足任一即停止本轮，按 `ledger.yaml` 的判定输出结论：

1. 已完成 5 场有效访谈（`consent: true` 且 Q1–Q5 均有回答）。
2. 已触达 15 个合格候选仍不足 5 场 → 结论是"渠道不可达"，不是"需求不存在"，需换渠道而非改数据。
3. `--eval` 已返回 kill（hard=strong=switched=0）→ 按诊断报告 §6.4 缩范围或改假设。
