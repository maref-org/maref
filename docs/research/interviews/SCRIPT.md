# 切换访谈（Switch Interview）执行脚本 v1.0

> 目的：验证「尺子假设」——即"是否有人愿意为 Agent 治理的可核验性付钱"。
> 铁律：**只问过去发生的事、只问已经花掉的钱和时间**。不问意愿、不问评价、不问"如果有个工具"。
>
> 配套：账本 `docs/research/interviews/ledger.yaml`；校验 `python3 scripts/interview_ledger.py --check`。

## 0. 访谈前（5 分钟）

| 项 | 要求 |
|---|---|
| 时长 | 30–40 分钟，最多 45 |
| 人数 | 1 对 1。多人会被"面子话"污染 |
| 记录 | 征得同意后录音；否则当场记关键数字。**同意必须显式**（账本 `consent: true`） |
| 身份 | 只记角色与机构类型，**不记姓名/手机/邮箱/微信**（脚本递归扫描键与自由文本，命中即拒收） |
| 前置 | 先发一段话说明"我不是来卖东西的，我在验证一个假设，可能被你说服放弃" |

开场话术（照读即可）：

> 我在验证一个假设：企业为「Agent 的行为可核验」这件事付钱。我的默认预期是**没人真的付钱**。
> 所以今天我不介绍产品，只想问过去 12 个月你们实际发生了什么、花了多少。
> 如果我理解错了，请直接说，这对我更有价值。

## 1. 五个必问（按顺序，不要跳）

**Q1 事故**
> 过去 12 个月，你们在 Agent / 自动化 / 模型上线这件事上，出过最贵的一次事故或返工是什么？
> 大概损失多少（钱 / 人天 / 客户）？

追问：谁被问责？最后怎么收场？有没有写复盘？

**Q2 举证**
> 上一次客户、甲方或审计问你"这个 AI 的决定凭什么算数"时，你交出去的是什么材料？
> 能把那份材料给我看一页吗（脱敏）？

追问：谁做的？做了多久？对方认了吗？不认的时候怎么补？

**Q3 已花的钱**
> 过去 12 个月，你为"证明 AI 的行为合规/可追责"这件事，实际买过什么？
> （测评、咨询、法务、外部审计、加班、临时外包……）

追问：金额区间、走哪个预算科目、谁批的。**没有就记 0，不要帮他找。**

**Q4 加班**
> 同一件事，你们团队自己贴进去多少小时？最近一次是什么时候？

追问：是常态还是偶发？下次还会不会再来一遍？

**Q5 砍预算**
> 如果下季度预算砍 30%，这块你会先砍还是最后砍？为什么？

追问：如果"最后砍"，是因为合规压力、客户合同，还是老板要求？谁的要求？

## 2. 只在最后问一次（不加追问）

> 如果有一个东西能让上面这些举证工作少一半，你愿意为它付多少钱？
> 或者：你希望我先给你出一份报价，还是先做一次试用？

- 说"愿意付 X"→ 追问"**什么时候能走采购流程**"，记 `signal: quote_requested` + `amount_cny`
- 说"先试用"→ 记 `signal: trial`，并约定试用验收标准
- 说"再看看/加个微信"→ 记 `signal: interest` 或 `none`，**不算信号**

## 3. 五条禁令（违反即本次访谈作废）

1. 不问"你觉得这个有价值吗"——评价不是证据。
2. 不问"如果有工具能自动生成证据链，你会买吗"——假设性问题只会得到礼貌的谎。
3. 不介绍产品功能，不演示 demo（除非对方明确要求，且已答完 Q1–Q5）。
4. 不帮对方回忆金额，不替他把"可能"升级成"花过"。
5. 不当场承诺价格、交付时间、合规结论。

## 4. 访谈后 10 分钟内（否则记忆会美化）

1. 填 `ledger.yaml` 一条记录（`id` 用 `INT-YYYYMMDD-NN`）。
2. `spend_cny` / `hours_wasted` 只填**对方说出口的数字**，没说就填 0。
3. 有材料的，脱敏后放 `docs/research/interviews/artifacts/`，路径写进 `artifacts:`。
4. 跑校验：

```bash
python3 scripts/interview_ledger.py --check          # 结构 + PII
python3 scripts/interview_ledger.py --eval --json     # 信号汇总
```

5. 若 `--eval` 返回 **exit 3（kill）**：不要改数据去救它。这意味着"到目前为止没找到愿付钱的人"，
   是有效结论——按诊断报告 §6.4 的口径，应当缩小范围或改假设，而不是加样本凑数。

## 5. 判定口径（与 `scripts/interview_ledger.py` 一致）

| 类别 | 条件 | 能证明什么 |
|---|---|---|
| hard | `would_buy.signal == paid` | 有人真付过钱（仍需合同/发票升级为 L3） |
| strong | `quote_requested` / `trial` | 进了采购或试用流程，尚未成交 |
| switched | `spend_cny > 0` 或 `hours_wasted > 0` | 过去真的为此付出过代价（最硬的行为证据） |
| kill | 访谈 ≥ 5 且 hard=strong=switched=0 | **需求假设被早期否证** |

> 注意：`switched` 单独成立并不能证明"会买我们的东西"，只能证明"问题真实存在且有成本"。
> 从 switched 到 paid，中间还差一次采购决策——这才是真正要验证的东西。
