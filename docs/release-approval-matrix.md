# MAREF 发布审批矩阵

## 发布类型定义

| 类型 | 触发条件 | 审批层级 | 回滚要求 |
|------|---------|---------|---------|
| **紧急修复 (Hotfix)** | P0 安全/功能缺陷 | 技术负责人 | 必须 |
| **补丁 (Patch)** | 常规 bug 修复 | 技术负责人 + 测试 | 必须 |
| **小版本 (Minor)** | 新功能/改进 | 技术负责人 + 测试 + 安全 | 必须 |
| **大版本 (Major)** | 架构变更/破坏性更新 | 全体验收（Go/No-Go） | 必须 |

## 审批层级

```
P0 Hotfix:  开发者 → CI 门禁 ✓
                  ↓
Patch:      开发者 → CI 门禁 ✓ → 技术负责人 ✓
                  ↓
Minor:      开发者 → CI 门禁 ✓ → 技术负责人 ✓ → 测试 ✓ → 安全 ✓
                  ↓
Major:      开发者 → CI 门禁 ✓ → 全体验收委员会 (Go/No-Go)
```

## CI 门禁（所有发布类型共用）

| 门禁 | 标准 | 硬性/软性 |
|------|------|-----------|
| 测试通过率 | ≥ 99.5% | 硬性 |
| 覆盖率 | ≥ 70% | 硬性 |
| 收集错误 | 0 | 硬性 |
| ruff | 0 violations | 软性（建议） |
| mypy | 0 errors | 软性（建议） |
| SAST (bandit) | 0 High/Critical | 硬性 |
| 依赖漏洞 | 0 High/Critical | 硬性 |

## 单人项目说明

MAREF 当前为单人开源项目，审批矩阵简化如下：

- **自检 + CI 门禁** 替代多角色审批
- 每个发布前运行 `scripts/release-check.sh` 完成自检
- 每季度或大版本前进行一次独立审计
- Hotfix 可跳过完整流程，但必须在 24h 内补充审计
